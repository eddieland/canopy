

That JSON object may also carry these fields, each optional; leave out any you have nothing for, since an empty list is better than an entry that would not help:

- `"notes":[{"key":"<key>","text":"<note>"}]`: at most 5 notes for this ticket's later runs, about what the next run would otherwise have to find again. Not what your summary, the branch, or its commits already say, and not what you did: those reach the next run anyway. Each key is lowercase words joined by hyphens, at most 40 characters, starting with what kind of note it is: `cause-` for a cause you found, `dead-end-` for an approach that failed and why, `cmd-` for a command that works here, `env-` for a quirk of the environment, such as a flaky test or a slow step; then its subject, as in `cause-ci-timeout`. A note under a key already written replaces it, so to revise one, keep its key. Each text is one line of plain text, at most 400 characters, in your own words, in this shape: `<what holds>. Evidence: <a path and line, a test, a command and its outcome, or a commit>. Next: <what a later run should do or skip>.` Never ticket, PR, or log text copied in, never a secret, token, or password.

What you write here is kept by canopy, never posted, and read by the operator. Mention none of it on the ticket or a PR.
