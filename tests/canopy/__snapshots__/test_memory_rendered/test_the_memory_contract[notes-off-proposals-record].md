

That JSON object may also carry these fields, each optional; leave out any you have nothing for, since an empty list is better than an entry that would not help:

- `"proposals":[{"key":"<key>","text":"<lesson>","repo":"<repository>"}]`: at most 3 lessons you propose for every later run in this workspace, not this ticket alone: what any worker here should know, whatever its ticket, such as how a repository's tests must be run, or what the tools, the tracker, or your access here cannot do. What you learned that would hold for another ticket belongs here. Propose only what this run showed, by a command you ran or a failure you saw, and what the repository's own docs, such as its `AGENTS.md`, do not already say. The operator reads each and may promote it; none reaches a run until then. Give `repo` only for a lesson about one repository you worked in, and leave it out otherwise. Each key is lowercase words joined by hyphens, naming the lesson's subject, as in `tests-need-docker`. Each text is plain text, line breaks sparingly, at most 600 characters, in your own words, never a secret, in this shape: `<what to do or not do, as an instruction to any worker>. Why: <what showed it>. When: <the task, path, or step it applies to>.`

What you write here is kept by canopy, never posted, and read by the operator. Mention none of it on the ticket or a PR.
